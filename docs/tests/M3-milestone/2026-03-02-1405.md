## 발견된 버그 및 개선 필요 사항

### BUG-01 (심각도: HIGH) — F-06 채팅 API 픽스처 URL 오류

**파일:** `backend/tests/api/test_chat_api.py` (line 35)

**문제:** `/api/v1/companies` (trailing slash 없음)로 POST 요청 → 307 Redirect 발생 → JSON 파싱 실패

**수정 방법:**
```python
# 변경 전
company_resp = await client.post("/api/v1/companies", ...)
# 변경 후
company_resp = await client.post("/api/v1/companies/", ...)
```

**영향:** F-06 채팅 API 테스트 11개 전체 ERROR 상태

### BUG-02 (심각도: MEDIUM) — F-02 사업장 목록 응답 형식 불일치

**파일:** `backend/app/api/v1/companies.py` (line 104) 또는 `backend/tests/api/test_companies_api.py` (line 135)

**문제:**
- `GET /api/v1/companies/`는 `CompanyListResponse` 반환 (`{"data": [...], "pagination": {...}}`)
- 테스트는 `{"success": true, "data": [...]}` 형식 (`ApiResponse` 래퍼) 기대

**선택지 A (API 수정):** 라우터에서 `CompanyListResponse` 대신 `ApiResponse`로 래핑하여 반환
**선택지 B (테스트 수정):** 테스트에서 `data["data"]`가 아닌 `data["data"]` (현재 스키마의 루트 `data` 필드) 접근

**담당 에이전트:** backend-dev (F-02)

---

### BUG-03 (심각도: MEDIUM) — F-02 사업장 수정 시 work_rule_required 미동기화

**파일:** `backend/app/services/company_service.py` (`update_company` 메서드)

**문제:**
- DB에 check constraint `ck_company_work_rule_required` 존재: `work_rule_required = (employee_count >= 10)`
- `update_company`에서 `employee_count`만 변경하고 `work_rule_required`를 재계산하지 않음
- `employee_count: 5 → 15` 업데이트 시 `work_rule_required`가 False 유지되어 check constraint 위반

**수정 방법:** `update_company` 서비스에 `employee_count` 변경 시 `work_rule_required` 자동 재계산 로직 추가:
```python
if employee_count is not None:
    work_rule_required = employee_count >= 10
```

**담당 에이전트:** backend-dev (F-02)
